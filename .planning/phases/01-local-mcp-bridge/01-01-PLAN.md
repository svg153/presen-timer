# PLAN 01-01 — Puente MCP local

## Goal

Que un agente conversacional (Claude Code, GitHub Copilot, Cursor…) pueda **definir la estructura de la
presentación** y **gobernar el temporizador** de una pestaña abierta, sin cuentas, sin tokens, sin nube y
sin coste.

## Approach

Un proceso local arrancado por el propio cliente MCP habla dos idiomas a la vez:

```
Cliente MCP ──stdio (JSON-RPC)──► mcp/server.mjs ──WebSocket 127.0.0.1──► pestaña en http://localhost
```

El proceso se lanza bajo demanda y muere con el cliente. El WebSocket se enlaza a `127.0.0.1`, así que
no hay superficie de red que proteger y no hace falta autenticación (D-03).

El contrato del protocolo vive en `shared/mcp-protocol.js`, importado por **los dos lados** (D-08): el
servidor Node y el navegador comparten los mismos nombres de comando y el mismo formato de duración. Eso
permite que la fase 02 añada un transporte HTTP sin reescribir la capa de comandos.

## Tareas

### T1 — Módulo de protocolo compartido

**Ficheros:** `shared/mcp-protocol.js`, `shared/mcp-protocol.d.ts`
**Requisitos:** MCP-01, BRG-01, BRG-02

- ESM puro, sin dependencias, importable desde Node y desde el navegador a través de Vite.
- Constantes: `PROTOCOL_VERSION`, `DEFAULT_BRIDGE_PORT` (8765), `STORAGE_KEY`.
- `TIMER_TOOLS`: catálogo declarativo con `name`, `title`, `description` y esquema de argumentos de cada
  herramienta. **Es la única fuente de verdad**: el servidor MCP construye su registro a partir de aquí
  y el navegador valida contra aquí.
- `COMMANDS`: los 14 nombres de comando.
- `parseDuration(value)`: acepta `"5m"`, `"1h"` y segundos en número o cadena; devuelve segundos o `null`.
- `formatTime(seconds)` de `src/utils/timerUtils.ts`: el formateador de la app, reutilizado por `buildSnapshot`. No se duplica en el protocolo.
- Constructores de mensajes: `hello`, `state`, `command`, `result`, `welcome`, `ping`.
- Tipos TypeScript en el `.d.ts`.

**Aceptación:** `node --input-type=module -e "import('./shared/mcp-protocol.js')"` funciona; el catálogo
contiene exactamente 14 herramientas (MCP-01…MCP-11); `parseDuration` acierta en `5m`, `1h`, `300` y
rechaza `abc`, `-5`.

### T2 — Servidor MCP y puente WebSocket

**Ficheros:** `mcp/server.mjs`
**Requisitos:** MCP-02…MCP-13, BRG-03, BRG-04, SEC-01, SEC-02

- `McpServer` del SDK 1.30 con `registerTool` para las 14 herramientas, tomando nombre, título,
  descripción y esquema del catálogo de `shared/mcp-protocol.js`.
- **Todos los registros por `console.error`.** Ningún `console.log`.
- `StdioServerTransport` para hablar con el cliente MCP.
- Servidor WebSocket con `ws` enlazado a `127.0.0.1`, con comprobación de `Origin` limitada a localhost.
- Correlación comando/respuesta por `id` con tiempo límite (5 s) y error explícito si se agota.
- Instantánea de estado cacheada; `timer_get_state` responde de inmediato con la última recibida.
- Arranque: `--port` y `PRESEN_TIMER_MCP_PORT`; si el puerto está ocupado, mensaje claro en `stderr`.
- Mensaje de bienvenida en `stderr` con las instrucciones de uso (URL de la app y configuración).

**Aceptación:** `npm run mcp` arranca, imprime la ayuda en `stderr` y no escribe **nada** en `stdout`
antes de que llegue una petición del cliente.

### T3 — Capa de comandos en el navegador

**Ficheros:** `src/mcp/commands.ts`
**Requisitos:** MCP-02…MCP-13, BRG-01, BRG-05

- `applyCommand(name, args, timer)` → `{ ok: true, value }` o `{ ok: false, error }`.
- Traduce cada comando a los callbacks de `useTimer`:
  `setSections`, `toggleTimer`, `resetSection`, `nextSection`, `prevSection`, `jumpToSection`,
  `addExtraTime`, `endPresentation`.
- Reutiliza `parseDuration` para aceptar `"5m"`, `"1h"` y segundos.
- Valida los argumentos **antes** de tocar el temporizador: índice fuera de rango, nombre vacío o
  duración inválida devuelven error y no cambian nada.
- `snapshot(timer)` construye la instantánea usando `calculateTotalDuration`, `calculateProgress` y
  `formatTime`.

**Aceptación:** cada comando del catálogo tiene su rama; un índice fuera de rango no lanza excepción y
devuelve `ok: false`.

### T4 — Puente en el navegador

**Ficheros:** `src/mcp/useMcpBridge.ts`
**Requisitos:** BRG-02, BRG-04, BRG-05, BRG-06, UI-01, UI-02

- Estado expuesto: `status` (`idle` | `connecting` | `connected` | `unavailable` | `error`),
  `sessionId`, `lastError`, `reconnect()`.
- **Si `location.protocol === 'https:'` no se conecta**: pasa a `unavailable` con el motivo. Evita el
  bucle de reintentos inútil contra la web de GitHub Pages.
- Reintento con retroceso exponencial (1 s → 2 s → … → 30 s) hasta que el servidor aparezca.
- Los callbacks del temporizador se guardan en un `useRef` para que el WebSocket se cree **una sola vez**.
- Envía la instantánea de estado al conectar y cuando cambia (comparando el valor serializado, no en cada
  render).
- Responde a cada `command` con el `id` recibido.
- Limpieza completa al desmontar: cierra el socket y cancela los temporizadores de reintento.

**Aceptación:** con el servidor apagado, el estado oscila entre `connecting` y reintentos sin llenar la
consola de errores; al arrancar el servidor, pasa a `connected` sin recargar la página.

### T5 — Indicador de estado en la interfaz

**Ficheros:** `src/components/McpBridgeStatus.tsx`, `src/pages/Index.tsx`
**Requisitos:** UI-01, UI-02, UI-03, DOC-03

- Punto de color + texto según el estado del puente.
- En `unavailable` (página HTTPS) muestra el aviso de contenido mixto explicando que hay que abrir la app
  en `http://localhost`, **sin** lenguaje de error.
- En `connected` muestra el identificador de sesión.
- Panel desplegable con la **configuración lista para copiar** al cliente MCP (fragmento JSON del
  servidor stdio) y los comandos de arranque.
- Integrado en `Index.tsx` recibiendo el temporizador, y visible también cuando no hay secciones
  definidas (que es justo cuando el agente va a crear la estructura).

**Aceptación:** los cinco estados se renderizan; en el sitio HTTPS público aparece el aviso, no un error.

T1 es la base: sin el protocolo compartido, T2 y T3 se construyen sobre arena.

## Riesgos

| Riesgo | Mitigación |
|--------|------------|
| `console.log` corrompe stdio | Prohibido; solo `console.error` |
| Dos copias de Zod | `zod` a `^4.6.5`; comprobado con `npm ls zod` |
| El bundle público engorda | `mcp/` no se importa desde `src/`; se inspecciona `dist/` |
| Puerto ocupado | Aviso claro; `--port` y variable de entorno |
| Reintentos contra la web HTTPS | El puente no se conecta si el protocolo es `https:` |
| Comando sin respuesta | Tiempo límite de 5 s y error explícito |
